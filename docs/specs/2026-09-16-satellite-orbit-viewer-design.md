## 1. 项目概述

### 1.1 一句话描述
一个纯前端（无后端、无 API Key、离线可用）的 3D 可视化页面：把在轨人造卫星的轨道、地球，以及卫星"拍摄范围"以好看的视觉效果呈现出来；点击卫星即放大并锁定跟随；支持用户自行添加任意轨道。

### 1.2 目标用户与场景
- 航天爱好者：想直观看看"头顶上有什么"。
- 教学/科普：讲轨道类型（赤道、极地、太阳同步、GEO、大椭圆）时一眼看懂差异。
- 汇报/演示：需要一张好看的轨道可视化截图或动态演示。
- 开发者：clone 下来改改就能做自己的卫星可视化 demo。

### 1.3 非目标（本期明确不做）
- 不作轨道预报、碰撞预警、入轨计算工具；**不追求数值精度**（目标：视觉真实、类别正确、量级正确）。
- 不接实时数据流、不做用户系统、不做后端、不做数据库。
- 不做地面站过境/可见性窗口计算（P2 彩蛋，见 D9）。
- 不做移动端原生 App（但网页在手机上要能看、能转、能点）。

### 1.4 成功标准
1. `git clone` → `npm install` → `npm run dev`，**零配置、零联网**即可运行。
2. 打开页面 3 秒内出画面；操作时帧率 ≥ 40fps（中档画质，集显笔记本）。
3. 点击任意卫星 → 1 秒内平滑放大并锁定，卫星始终在画面中央，拍摄范围高亮跟随移动，无明显抖动。
4. 从赤道低轨到地球静止轨道再到大椭圆轨道，均能正常显示、取景合理、不穿模、不闪烁。
5. 用户能在 UI 里 3 步内添加一颗自定义卫星，并可用预设一键生成极轨/太阳同步/GEO/Molniya。

## 2. 核心体验（三个必须做好的瞬间）

1. **初见**：深空背景，地球缓慢自转，大气边缘有光晕，一条条轨道线静静悬着，卫星像小光点沿线流动。
2. **锁定**：点一颗卫星，相机平滑推进，地球在下方缓缓流动，目标卫星稳稳定在中心；一个半透明光锥从卫星投到地面，落点处亮起一圈高亮区域，随卫星在地面扫过。
3. **自定义**：在面板里填 6 个轨道根数（或粘一段 TLE），点"添加"，一条新轨道立刻出现在场景里。

## 4. 轨道类型兼容性设计

对应"兼容不同运行轨道高度以及赤道、极地和高点轨道类型"的落地方式。

**预制卫星：9 类 × 2 颗 = 18 颗，全部为真实在轨卫星 + 真实 TLE**（清单见 §17）。

| 类型 | 判定规则（运行时由轨道根数计算） | 预制卫星 | 视觉要点 | 相机锁定策略 |
|---|---|---|---|---|
| 赤道低轨 | 高度 < 2000 km 且 倾角 < 10° | IXPE、NuSTAR | 地面轨迹贴赤道东西向来回 | 近距离跟随，能看到地球曲率 |
| 极轨 | 高度 < 2000 km 且 80° ≤ 倾角 ≤ 95° | ICESat-2、CryoSat-2 | 地面轨迹南北向并覆盖两极 | 跟随 + 可切极点俯视 |
| 太阳同步 | 高度 < 2000 km 且 95° < 倾角 ≤ 106° | Landsat 9、Sentinel-2A | 每天大致同一地方时过境 | 中近距离跟随 |
| 低轨 LEO | 其余高度 < 2000 km | ISS、风云三号G | 最常见，移动快 | 近距离跟随 |
| 中轨 MEO | 周期 600–1400 min | GPS、北斗 MEO | 轨道圈明显，周期约 12h | 中距离跟随 |
| 倾斜同步 IGSO | 周期 1400–1480 min 且 倾角 ≥ 5° | 北斗 IGSO、QZSS | 在地面画"8"字 | 中远距离跟随 |
| 地球静止 GEO | 周期 1400–1480 min 且 倾角 < 5° | 向日葵9号、GOES-18 | 相对地球几乎不动，轨迹是一个点 | 特殊：相机拉远，地球占屏幕约 1/3 |
| 大椭圆 HEO | 偏心率 > 0.25 且 近地点 < 2000 km | ARKTIKA-M 2、MERIDIAN 8 | 近地点飞快、远地点极慢，视觉冲击强 | 距离随高度自适应，避免近地点穿模 |
| 逆行 | 高度 < 2000 km 且 倾角 > 106° | EROS C3、遥感五十号01 | 相对地面高速反方向运动 | 同普通低轨 |

分类规则说明：
1. 匹配优先级自上而下：大椭圆 → 静止/倾斜同步 → 中轨 → 低轨细分。
2. 低轨中 95°–106° 倾角事实上就是太阳同步轨道，故"逆行"单列为倾角 > 106° 的高倾角逆行。
3. 分类在运行时由轨道根数算出，用户自添加的卫星同样会被自动归类并显示标签。
4. 数据实测（2026-09-16，Celestrak 全量在轨约 1.1 万颗）：倾角 > 106° 的目标全目录仅 9 颗，其中近地点 < 2000 km 的仅 6 颗，已从中选定两颗真实遥感卫星。

实现要点：
1. 位置与轨道根数由传播器统一给出（见 §8）；类别由上述规则实时判定，UI 只做展示与标签。
2. 轨道线采样点数按周期与偏心率自适应，椭圆轨道近地点附近加密采样。
3. 相机锁定距离规则：`d = clamp(轨道高度 × 1.5 + R × 0.8, 2.5R, 12R)`；GEO 单独给定最小距离以保证地球与卫星同框。
4. 可选"轨道高度压缩视图"（P2）：对地心距做单调压缩映射让 LEO 与 GEO 同屏；默认关闭（真实比例），开启时几何仍在真实空间计算后再映射，保证自洽。

## 5. 视觉与交互规格（美术方向）

- 基调：深空黑蓝背景（#05070f）+ 地球冷白/蓝绿 + 选中高亮橙金（#ffb547）+ 拍摄范围青绿发光（#39e6c3）。
- 风格建议：**混合风**——写实地球贴图打底，配科技感 HUD、发光轨道线、扫描光环；既有质感又不廉价。
- 动效：相机移动统一 `cubic-bezier` 缓动 0.9–1.2s；高亮区边缘缓慢呼吸（±3% 半径，2.5s 周期）；锁定时光锥有一次 0.6s 的扫出动画。
- 明确避免：卫星点用纯色方块、轨道线无透明度渐变、默认蓝色按钮式面板。
- 交互反馈：悬停 → 放大 1.6× + 名称气泡；点击 → 选中环 + 面板滑入 + 相机过渡；锁定中 → 顶部显示"已锁定 XXX / 解除"。

## 6. 技术选型

| 项 | 选择 | 理由 / 备选 |
|---|---|---|
| 构建 | Vite + TypeScript | 零配置、秒级热更新；产物可静态托管 |
| 3D | three.js（WebGL2） | 生态最全；备选 Babylon.js（本项目用不上其重型特性） |
| 轨道算法 | satellite.js（SGP4）+ 自研 Kepler+J2 | TLE 解析/传播/坐标转换一次搞定；自研部分服务于手动根数输入 |
| UI | 原生 TS + DOM（轻量 Store 订阅） | 依赖少、体积小；备选 React（见 D4） |
| 折线渲染 | three 自带 Line2/LineMaterial | 支持线宽 >1px 且抗锯齿，观感更好 |
| 后期 | EffectComposer + UnrealBloomPass | 发光效果的关键 |
| 测试 | Vitest（单元）+ 人工视觉验收清单 | 几何/传播可测，渲染靠人眼 |
| 规范 | ESLint + Prettier | 开源项目基本盘 |

明确不引入：框架运行时（除非 D4 改选）、任何后端、任何需要 Key 的服务、任何运行时 CDN 依赖（保证离线可用）。

资源策略：
- 地球贴图：NASA 公有领域影像（Blue Marble / 夜间灯光），压缩后随仓库分发（约 2–4MB），README 注明来源与许可；缺失时自动退化为程序化纹理，页面仍可用。
- 星空：程序化生成，零外部资源。
- TLE：离线快照 JSON，随仓库分发（见 §9）。

## 7. 架构与模块

数据流（单向）：

```
TLE/根数输入 → Catalog(目录) → Propagator(传播) → 每帧状态
                                                  ├→ 3D 图层(轨道线/卫星点/地面轨迹)
                                                  └→ 拍摄范围图层(球面高亮+光锥+条带)
SimClock(时间) ─────────────────────────────────→ 各图层 & UI
Store(选中/悬停/图层/画质) ─────────────────────→ UI 面板 & 相机控制器
```

## 8. 关键算法与几何

### 8.1 坐标系与时间
- 场景世界坐标 = **ECI（惯性系）**，地球网格每帧绕 Z 轴旋转 GMST 角度。
  好处：轨道线在惯性系中静止，卫星位置由 SGP4 直接输出，无需每帧坐标变换。
- 地面相关物（星下点、拍摄范围、地面轨迹、城市）在 **ECEF** 中计算，再旋转 GMST 到 ECI 渲染——这样它们贴在地面上随地球转动。
- 说明：SGP4 输出 TEME 系，与严格 J2000 约有 0.1° 差异；本项目按惯例把 TEME 当惯性系使用（satellite.js 亦如此），影响远小于视觉容差。

### 8.2 传播

```ts
interface Propagator {
  positionEci(t: Date): { x: number; y: number; z: number }; // km
  velocityEci(t: Date): { x: number; y: number; z: number }; // km/s
  periodSeconds(): number | null;      // 用于采样轨道线
  elements(): KeplerianElements | null;
}
```

- `Sgp4Propagator`：`twoline2satrec` + `propagate`。
- `KeplerJ2Propagator`：由 a/e/i/Ω/ω/M0 出发，加入 J2 长期项（Ω̇、ω̇、Ṁ），牛顿迭代解开普勒方程，再求位置速度。
- 两者都提供 ECEF 与大地坐标（经纬高）派生方法。

### 8.3 拍摄范围几何（核心）

设卫星 ECEF 位置 P（|P| = r），地球半径 R = 6371 km，半视场角 α，指向单位向量 d（默认星下点方向 −P̂，可叠加侧摆角）。

- **正下视解析解**：地面高亮区的地心角
  `λ = asin(r · sinα / R) − α`
  边界是球面上以星下点为圆心、角半径 λ 的圆。地平线极限 α_max = asin(R/r)，此时 λ = acos(R/r)。
- **通用解法（含侧摆、含超地平线）**：绕锥轴按方位角均匀取 N 条边界射线（N=64~128），逐条与球面求交
  `t² + 2t(P·d) + (r² − R²) = 0`，取近根为落点；无交点时钳制到切点。所得点串即高亮区边界（侧摆时呈椭圆状，符合真实情况）。
  两种解法互为校验：单元测试用正下视解析式核对采样结果（误差 < 1e-6 rad）。
- **渲染三件套**：
  1. 球面高亮：边界点 + 中心点构成三角扇，顶点半径 R×1.002，加色混合、半透明渐变、边缘描边；
  2. 光锥：卫星点到边界点之间的侧表面（三角带），加色半透明，靠卫星端更亮；
  3. 扫过条带：保留最近 N 分钟的高亮区边界，形成带状网格，边缘更亮。
- **性能**：每颗卫星每帧约 70 个顶点运算，50 颗同时显示也只有约 3500 次向量运算/帧。几何复用 `BufferGeometry` + `setDrawRange`，避免每帧分配内存。

### 8.4 拾取与相机跟随

- 拾取：较少卫星直接用 `Raycaster` 对点集求交；若做全量模式则改 GPU 拾取（ID 渲染到离屏缓冲后回读像素）。
- 跟随实现（交互成败的关键）：
  1. 点击后约 0.9s 缓动：相机位置与目标点同时从当前状态插值到跟随状态；
  2. 跟随状态下每帧 `controls.target = 卫星位置`，相机位置 = 卫星位置 + 用户偏移向量；用户拖拽只改变偏移量，得到"边跟边转"的手感；
  3. 锁定瞬间略收缩 FOV，制造推进感；
  4. 对卫星位置做一阶低通滤波（尤其高倍速下）避免抖动。
- 距离规则见 §4。

### 8.5 时间与传播的性能策略
- 默认目录约 120–300 颗：每帧全量传播可接受（SGP4 单次约 5–20 µs）。
- 全量模式（可选，数千至上万颗）：位置更新降到 4–10 Hz 并在帧间线性插值；轨道线只画选中/收藏项；关闭 Bloom；必要时把批量传播移入 Web Worker（第一版预留接口，按需实现）。
